# 架构层全量质检

`audit_editorial_integrity(review_id)` 与 `GET /api/editorial-reviews/{id}/integrity` 对同一份已有会话执行只读审计。核心实现在 `backend/app/editorial_integrity.py`，HTTP 与 MCP 都调用 `Editorials.integrity`，使用现有账号隔离和来源访问检查。

## 检查内容

| 层 | 核对方式 |
| --- | --- |
| 正文身份 | 重算整稿哈希和每章每段清单；核对章节、段落、选择范围和顺序 |
| 来源链 | 重算完整冻结来源对象的哈希，将来源正文规范化后逐段比对基线 |
| 补丁链 | 从基线按真实批次重放全部已应用补丁；检查改前、改后哈希、锚点、同段冲突及章节修订，最终与当前全文比对 |
| 审读证据 | 对应每份报告产生时的正文快照核验引文、Unicode 码点、哈希、分块边界及跨章范围 |
| 复核证据 | 核对历史复核的正文版本及关联位置；已复核标记必须有当前稿的实际记录与专项改善判断 |
| 覆盖声明 | 从实际分块与历史报告重新统计冻结覆盖，不直接信任保存的汇总数字 |
| 事实及故事 | 对已登记的事实、实体、关系、知情和逐章记录核验证据；没有记录时显示未登记，不作通过结论 |
| 实际交付 | 对比冻结对象与会话记录；核验七种实际文件、EPUB 阅读顺序及段落、TXT/Markdown 全文、JSON 对象以及 ZIP 内外文件和清单 |

审计还运行当前 `scan`，返回全范围规则候选数量、涉及章节、约束计算和有界模式检索范围。它不修改旧扫描、问题处置、覆盖、审稿修订或冻结版。

## 结果边界

- `integrity_passed` 表示数据链的检查未发现破坏；不代表文学质量通过。
- `declared_completion` 保留冻结时的验收快照。`current_workflow` 按当前规则重新计算；版本升级后的只读扫描不冒充写入了新扫描覆盖。
- `scope.whole_book` 明确是全书还是所选范围。`literary_reread_performed` 固定为 false，因为工具不执行模型阅读。
- `acceptance_gaps` 明确缺少结构化事实、计算约束和故事覆盖等限制；不存在记录不等于小说没有对应内容。
- 冻结版本不因新的规则版本被改写。新的语义审读或结构化全书核对，应从准确的最新精修版建立对应会话。

## 规则处置失效修复

`editorial-4` 为每条规则候选保存 `scan_basis_sha256`：它绑定规则版本、候选的实际证据及判断字段，以及关联事实/约束或故事记录的内容。稳定的 `scan_key` 仍定位问题，不再被用来暗示处理理由仍然有效。

重扫时，已 resolved/dismissed 的候选若依据不同，转为 needs_recheck。事实或故事依赖失去确认时，旧 dismissed 也需重新复核。依据完全相同的重复扫描保留已有处置。旧记录缺少依据指纹时保守地要求复核一次；冻结快照不变。

新增隔离回归分别复现了数值改变、解释改变但算式不变、事实失去确认三种旧结论未失效的错误。审计测试另外验证导出损坏、来源错配、补丁哈希损坏、伪造引文、覆盖数字不实、选择范围和账户边界。

## 运行

```bash
uv run python scripts/audit_editorial_integrity.py \
  --review-id 审稿会话ID \
  --output output/architecture-audit.json
```

脚本使用新 STDIO MCP 进程与原有认证配置，验证工具发现和只读属性，再比较调用前后的会话状态。退出码 0 只表示数据完整性通过；文学与结构化验收须继续阅读结果中的缺口。它不会打印密钥，也不会重新创建生产小说或改写正文。

隔离验证使用合成样本，覆盖来源、补丁、证据、导出损坏、所选范围和账号隔离。当前发布的实际验证结果见 [VALIDATION.md](VALIDATION.md)。
